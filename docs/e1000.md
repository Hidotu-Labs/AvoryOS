# e1000 bring-up

The native driver currently supports **Intel 82540EM, PCI 8086:100e** (QEMU
`-device e1000`). Other e1000 variants and e1000e are not matched.

## Implemented: stages 1–6

Network startup now activates NICs through the optional `net_device_ops.start`
callback. An omitted callback means the device is already active. Failed starts
are stopped and removed from the network registry; the first successfully
activated NIC becomes the default. Protocol initialization runs once, independently
of the NIC driver. Without a usable NIC it skips protocol initialization and DHCP
and continues booting. Restarting the main session does not duplicate network
workers or protocol initialization.

Registering a network device with an empty name assigns the first available
`ethN`; explicit names retain duplicate-name checks. RTL8139 uses automatic naming
and the common activation path.

The e1000 device-model probe validates the BAR0 layout and size, establishes
uncacheable MMIO mappings, disables bus mastering and interrupts, resets the
controller with a TSC deadline, and obtains a valid unicast MAC from RAR0 or
EEPROM. It logs PCI identity, MAC and current link status. Each PCI function owns
separate state. Activation allocates one 256-entry legacy descriptor ring per
direction, plus 2 KiB buffers per descriptor, using coherent write-back DMA RAM
below 4 GiB. Data and descriptors are published before MMIO doorbells. TX copies
and pads frames, reserves an empty ring slot, reclaims completions and reports
queue saturation. RX validates descriptor status, errors and frame length,
discards unsupported multi-descriptor packets, and copies accepted frames into
the existing network worker queue before recycling their DMA buffers.

INTx uses the native PCI interrupt layer and tolerates shared interrupt lines.
Each handler reads the interrupt cause once, processes at most a ring of RX
descriptors, and explicitly requests another interrupt if more completed RX
descriptors remain. Broadcast and all multicast frames are accepted for DHCP
and IPv6 NDP; checksums are handled in software. MTU is 1500; jumbo frames,
TSO, VLAN and checksum offload are not enabled.

Stop disables RX/TX, masks interrupts and bus mastering, and resets the device
before freeing DMA allocations. If reset times out, those allocations are
quarantined until reboot. Stable control blocks, shared HHDM MMIO mappings and
one installed IRQ callback per slot remain resident until reboot: queued packets
and sysfs references retain valid addresses, and the current IRQ registry lacks
a concurrent uninstall grace period. Rebind reuses the slot and IRQ callback.

One service thread checks all controllers every 100 ms. It reclaims completed
TX descriptors even if an interrupt was lost and recovers a queue that has made
no completion progress for two seconds while carrier is up. Link-down time does
not trigger watchdog resets; new transmissions fail promptly while disconnected.
Recovery logs the pending count, hardware head/tail and last interrupt cause,
resets the controller, and reuses its existing DMA allocations. Failed resets
leave the interface inactive and retain its DMA memory until reboot.

Start, stop, rebind, watchdog recovery and shutdown serialize through a task
context lifecycle guard. IRQ and transmit paths use a separate short spinlock;
reset/EEPROM waits run without holding that spinlock. A packet generation changes
on reset/stop/unregister so copied packets still queued from an earlier activation
are discarded. Rebinding a previously selected default NIC restores that selection.
Reboot, halt and power-off explicitly stop e1000 before machine shutdown, and a
shutdown flag prevents the service thread from restarting it.

Link changes are detected through LSC interrupts and periodic polling, counted
once per observed transition, logged from task context, and sent to userland as
`RTM_NEWLINK` notifications for the default interface. Native persistent interfaces
now expose live `carrier`, `operstate` and statistics files. In addition to existing
packet/error counters, `statistics/tx_timeouts`, `recoveries`, `recovery_failures`
and `dma_bytes` expose watchdog outcomes and retained DMA memory. A running e1000
owns 1,056,768 DMA bytes; a successful stop releases all of them. Permanent sysfs
callbacks are only used for drivers whose netdev addresses remain valid until
reboot; user-driver endpoints retain their prior snapshot behavior.

Both NIC drivers can activate together, but the protocol stack currently has
one default interface and one IPv4/IPv6 configuration. Secondary-interface traffic
does not update that configuration. RTL8139 remains the default when both drivers
are present. `net_default=eth1` on the kernel command line selects the first
e1000 instead; the selected name is logged at startup. Only the default interface
is currently exported by the existing sysfs/netlink/procfs network views.

## Validation

Interactive launchers with networking (`run`, `run-numa`, `run-minimal`,
`run-sata`, and `run-c7-prime`) accept `RUN_NIC=rtl8139` (default), `e1000`,
`both`, or `none`. For example:

```sh
make run RUN_NIC=e1000
make run RUN_NIC=both
make run RUN_NIC=both KERNEL_CMDLINE='net_default=eth1'
```

Build and run:

```sh
make -C kernel -j4
python3 scripts/tests/test_net_device_start.py
python3 scripts/tests/test_e1000_probe.py
python3 scripts/tests/test_e1000_probe_boot.py
# Build the kernel and run host tests and the complete 4-CPU boot matrix:
make test-e1000
# Longer stress with different CPU counts:
python3 scripts/tests/test_e1000_probe_boot.py --case e1000 --seconds 30 --smp 1
python3 scripts/tests/test_e1000_probe_boot.py --case e1000 --seconds 30 --smp 8
# NetworkManager discovery, live counters and HTTP SHA-256 integrity:
AVORY_NETWORK_TEST_NIC=e1000 python3 scripts/tests/test_network_statistics_boot.py
```

The boot test uses the existing ISO's bootloader plus the freshly built kernel
in private images under `build/e1000-probe-boot/`. It requires KVM, QEMU, the
musl toolchain, and the dependencies of `scripts/syscall-restart-boot.py`.
It never attaches `disk.img` or host PCI hardware.

Coverage includes no NIC, e1000 only, RTL8139 only, and two e1000 devices together
with RTL8139, selecting either driver as default. Checks cover binding, expected
MACs, active/stopped PCI command state, unbind/rebind, DHCP, a 1 MiB TCP echo with
byte-for-byte verification and ring wraparound, short/MTU-size UDP echoes, ICMP
echo, and IPv6 UDP through NDP/SLAAC. The IPv6 harness advertises
`2001:db8:1::/64`, because the existing stack only accepts global-unicast-shaped
SLAAC prefixes and does not accept QEMU's default `fec0::/64` prefix.

The matrix also injects one TX stall, verifies watchdog recovery and subsequent
DHCP/traffic, runs four concurrent TCP echo streams with per-block integrity
checks, toggles the selected e1000 through QMP during those transfers, checks live sysfs carrier/operstate
and route-netlink notifications, and verifies traffic after link restoration and
three rebind cycles. DMA footprint must remain constant and free memory may not
fall by more than 2 MiB across those rebind cycles. Each guest must power off with
DMA/INTx disabled and buffers released. `--seconds` controls sustained load time
(default 10), `--smp` selects 1/4/8 CPUs, and repeated `--case` options select cases.
Logs and the stripped kernel snapshot stay under `build/e1000-probe-boot/`;
other CPU counts use `smp1/` or `smp8/` subdirectories.

`e1000_test_tx_stall=1` is an explicit boot diagnostic used by the recovery case:
it suppresses initial TX doorbells until the watchdog resets the controller. It
is disabled by default and does not rearm on rebind. This verifies reset/recovery
in QEMU; host-side tests simulate reset timeouts and quarantine.

Host-side probes additionally cover failed-start fallback, automatic naming and
default selection, invalid BARs, ownership conflicts, mapping/reset/EEPROM
failures, invalid MACs, TX saturation/padding/completion errors, RX errors and
fragment chains, packet-pool exhaustion, bounded IRQ continuation, each partial
DMA allocation failure, IRQ registration failure, and reset quarantine.
They also cover watchdog deadlines, lost TX interrupts, skipping recovery while
a lifecycle change is in progress, link-down suppression, service-thread creation
failure, packet generations and repeated shutdown.

## Remaining scope

Physical-hardware validation, interrupt moderation, physical hot-remove and IRQ
callback reclamation, and per-interface protocol configurations remain separate
work. Hardware expansion, offloads and jumbo frames are also deferred. These tests
establish functional and recovery behavior under QEMU rather than physical
gigabit line-rate performance.

Hardware references: [Intel 8254x software developer's manual](https://www.intel.com/content/dam/doc/manual/pci-pci-x-family-gbe-controllers-software-dev-manual.pdf)
and [QEMU e1000 implementation](https://github.com/qemu/qemu/blob/master/hw/net/e1000.c).
